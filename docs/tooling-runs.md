# 开发命令与验收证据

Node.js 24 下，`npm run build`、`npm test`、`npm run check`、`npm run verify`、`npm run dev` 使用同一个工作区事务入口。`node scripts/build.mjs`、`check.mjs`、`simulate.mjs`、`serve.mjs` 也受保护。直接 check 只检查现有 dist，npm check 仍先构建。

同一真实工作区已有构建或读取事务时，新请求明确退出 75，不运行被拒绝的步骤。不同 clone 或 worktree 各有自己的事务，可以并行。verify 保留 build、原测试全集、再次 build、check、三个种子模拟和回放断言，并运行独立的工具行为测试。内部子步骤不再次调用受保护的 npm 命令，因此不会父子争锁。子 Node 测试以新的测试进程上下文启动，不继承 Node 内部的递归测试标记。

每次请求打印独占目录 `.audit/runs/run-*/`，其中包含：

- `start.json` 记录命令、参数、真实工作区、HEAD、dirty 状态、输入摘要和环境。
- `stdout.log` 与 `stderr.log` 保留本次独立输出。
- `result.json` 仅在终局独占写入一次，包含起止输入身份、步骤与实际子进程退出码或信号、最终结果。

成功验收必须有 `result.json` 且 `outcome.code` 为 0，起止输入身份相同。dirty 为 true 的运行仅证明当时的工作树，不能冒充干净 HEAD 的验收。输入摘要来自 Git 已跟踪及未忽略的普通文件字节，并区分文件类型；符号链接记录链接目标文本，不遍历链接指向的目录或声称摘要覆盖外部依赖树。其他不支持的特殊输入类型明确失败。被忽略的产物和运行日志不进入摘要。缺少终局记录、日志或结果写入失败、执行中输入变化都不能当成功。

外部 `> same.log` 发生在命令启动之前，工具无法阻止 shell 截断这个外部文件。提交验收证据使用独占 run 目录，而不是共享终端日志或“最后一次成功”文件。

正常失败传播实际非零码。SIGINT、SIGTERM 会停止后续步骤，终止并等待本次子进程组，再释放事务并记录信号。不会因收到信号就先释放仍有写进程的事务。该进程组实现支持 macOS 和 Linux，其他平台明确拒绝。

SIGKILL 和断电不能由 JavaScript 清理。遗留 `.audit/dist-transaction` 会保守拒绝新请求，不按 PID 或时间偷锁。恢复前必须检查其 `owner.json`、对应 run 及写入后代均已终止，再由操作者删除该事务目录；保留不完整 run 记录。这里没有自动强杀恢复，也没有清理历史证据的后台服务。

dev 构建后在事务内复制完整 dist 到本次 run，释放事务，再从独立快照服务。直接 serve 同样复制现有 dist。开发页固定为启动时版本，后续 build 不会破坏它；更新页面版本需重启服务。原 localhost 地址与 PORT 配置保留。服务仍运行不代表一次有限验收已成功完成。

其他独立历史诊断脚本没有自动取得该事务，仍须在空闲工作区运行。内部工作函数不是安全沙箱，不支持绕过公开入口并发调用；不要把这次修复描述成所有任意仓库脚本均受保护。

工具测试只在自己的临时工作区启动有限 fixture，不递归启动外层 verify。完整双 verify 与真实项目产物比较由作者和非作者验收分别执行。新工具机制不改变游戏模拟、输入回放、下载预算或资源。
