# 沙漠基地剧情与视听验收规格

本规格对应 [Issue #4](https://github.com/HYY-yu/LunarEchoes/issues/4)。[双语目录](../content/desert-base.story.json)是本任务对白的唯一来源，包含八条稳定 ID。当前交付只有内容、检查器和验收约定，没有接入游戏。沙漠地图、剧情播放、跳过、音效和解锁均未由本任务实现或验收。

## 剧情与目录

玩家是地球防卫部队的中继工程兵。失联警报将玩家带到沙丘中的基地，破损机库和雷达阵列承接求援任务。金属外壳下的活体组织证实外星入侵，恢复的遥测说明其他站点同样遇袭。玩家击退钻地收割机后发出求援，并收到雨林研究站的回应。雨林的数据再引向南极；月球来源留到南极定位，不在沙漠提前揭晓。

沙漠使用开阔沙地、设备间隙和机库残骸形成视觉路线。雨林后续使用林冠阴影、遗迹空地与盘根通路，不能只替换背景色和地名。装饰不承诺碰撞、掩体、阵列耐久或新的失败条件。“守住求援”是既有关卡结果的叙事表达。钻地收割机是已有 `boss` 的剧情名称，不引入钻地无敌或新的 `EnemyKind`。

| ID 后缀 | 内容职责 | 计划展示条件 | 结果限制 |
|---|---|---|---|
| `opening` | 失联警报、身份、求援动机 | 进入沙漠剧情 | `any` |
| `objective` | 击退入侵者、移动与冲刺提示 | 开战前并可在战斗中查阅 | `any` |
| `radio.first-contact` | 确认机械生物入侵 | 首次接敌后的叙事节点，当前无专用事件 | `any` |
| `radio.telemetry` | 扩大危机范围 | 中段叙事节点，当前无专用事件 | `any` |
| `boss` | 收割机逼近 | 沙漠接入后的 `boss` 事件 | `any` |
| `victory` | 求援成功、遥测保全 | 仅 `won` | `won` |
| `defeat` | 通讯中断、任务失败 | 仅 `lost` | `lost` |
| `next-clue` | 雨林回应与调查方向 | 胜利结局之后 | `won`，目标 `rainforest` |

表内顺序是目录顺序。胜利与失败是互斥分支，不是连续播放顺序。叙事节点不绑定新战斗计时；每关战斗仍为 180–300 秒，剧情与菜单不计入。具体时机交给后续技术与数值任务。

`StageDefinition.story` 未来按 ID 引用目录内容，映射为 `opening` → `desert-base.opening`、`objective` → `desert-base.objective`、`ending` → `desert-base.victory`、`nextClue` → `desert-base.next-clue`。失败由独立的 `desert-base.defeat` 展示规则控制。现有四字段契约没有失败路由，本任务不修改契约样例、不复制目录文本、不把该映射冒充已实现。技术 owner 决定接入方式。

采用扁平 `{id, stageId, beat, outcome, zh, en, nextStageId?}[]`，视听触发留在下表。曾比较将对白、触发和动画帧嵌套在场景树中的方案；本任务不需要场景解释器，分开保存能避免把计划事件误当成模拟能力。`outcome` 和唯一的 `nextStageId` 只表达内容展示限制，不执行解锁或决定重试行为。

## 跳过与双语行为约定

以下条款须在后续接入时以运行证据验收。

- 开场、结局和下一关线索均可跳过；战斗中的无线电可关闭。跳过只结束文字与表现，不派发战斗动作。
- 目标在跳过后仍可查阅。中英文切换使用同一 ID，不重置进度、不重复触发结果，也不丢失目标。
- 相同种子与动作序列在展示、跳过和切换语言后得到相同战斗 tick、随机状态、输入顺序、结果与 checksum。开场停留时间不消耗战斗时间。
- 失败只显示失败条目，不能显示胜利或雨林成功线索，也不能因跳过发生解锁。胜利线索不等于已经存在可玩的雨林入口。
- 延后显示的无线电在终局时取消，不能覆盖结局。跳过、关闭无线电的控件文本也须中英文，但控件由后续 UI owner 交付。
- 重试、持久解锁与跨关装备遵循待人类确认的方案，本规格不设定这些规则。

## 战斗状态与声音验收

源码依据为 [art.ts](../src/art.ts)、[render.ts](../src/render.ts)、[audio.ts](../src/audio.ts)、[core.ts](../src/core.ts) 和 [main.ts](../src/main.ts)。当前图集每种角色一个 16×16 帧，共用九色调色板。浮动、闪白和死亡粒子不等于完整的移动、攻击、受击和死亡状态帧。

| fixture ID | 事件或状态依据 | 未来验收内容 | 当前源码状态 |
|---|---|---|---|
| `desert.combat.move` | 玩家与敌人位置、移动状态 | 工程兵和各敌人移动朝向、身体节奏；窄屏仍能识别轮廓 | 静态图集，状态动画待制作 |
| `desert.combat.shot` | `shot` | 枪口与弹道可读，开火合成音不形成持续刺耳声 | 已有音色，动画和听感待验收 |
| `desert.combat.enemy-hit` | 敌人受击逻辑，无独立 Event | 与玩家受伤、击杀可区分的反馈和合成命中音 | 无独立敌人命中声音事件 |
| `desert.combat.kill` | `kill` | 死亡动作或粒子与击杀噪声同步，无残留碰撞暗示 | 已有粒子与音色，待实机验收 |
| `desert.combat.player-hit` | `hit`，仅玩家受伤 | 玩家闪白与低频受伤音同步 | 已有源码，待实机验收 |
| `desert.combat.pickup` | `pickup` | 拾取闪光与高音回执可辨识 | 已有音色，待实机验收 |
| `desert.combat.dash` | `dash` | 冲刺轨迹、冷却可读；噪声不盖过受伤 | 已有特效与音色，待实机验收 |
| `desert.combat.upgrade` | `upgrade` | 升级表现与恢复战斗无音符堆积 | 已有音色，待实机验收 |
| `desert.combat.telegraph` | 渲染预警状态，无专用 Event | 冲刺与定向攻击提前量可见，色弱下依靠形状也能区分 | 预警表达须实机验收 |
| `desert.ui.confirm`、`desert.ui.reject` | 计划 UI 行为，无 Core Event | 确认与拒绝有不同合成音和文字反馈 | 无声音映射 |
| `desert.audio.lifecycle` | 静音、暂停、失焦、后台、重开、终局 | 静音无泄漏、恢复不追播、重开无重复音乐、终局音只一次 | 待试听与运行验证 |

[Issue #5](https://github.com/HYY-yu/LunarEchoes/issues/5) 跟踪声音缺项与生命周期。`Synth.events` 当前只有 `shot`、`pickup`、`kill`、`hit`、`dash`、`upgrade`、`boss` 映射。`main.ts` 在终局先调用 `updateUi` 暂停音频，再调用 `Synth.events`；未来终局声音接入需要技术修正该顺序。`pause` 关闭后续调度，没有主动停止已启动的声音，尾音是否可闻须实际听音，不能由源码直接判定通过。

## 后续媒体与独立验收

visual_audio 在制作资源前搜索官方竞品实机参考，记录出处，并用 imagegen 概念图评审轮廓。概念通过后落实为代码像素图集。概念图不替代实际游戏画面，本次没有生成素材或发起媒体调用。

后续为每个 fixture 在桌面 1280×720 和窄屏 390×693 录制真实浏览器片段，记录 SHA、浏览器、设备、语言与 fixture ID。动画片段覆盖完整状态转换，静态截图只能证明构图。游戏使用 HUD、战场提示和剧情文本，避免 SaaS 仪表盘布局。中英文分别检查换行、遮挡、目标可查阅和跳过控件。声音录制包含合成背景乐、密集战斗、Boss、终局及完整生命周期，并提交试听记录。

本次结构验收入口为 `node scripts/desert-story.mjs` 和已有 `npm run verify`。检查器从真实 JSON 读取内容，拒绝重复 ID、缺少段落、乱序、无效关卡、空白语言和错误结果路由。变异输入测试验证拒绝行为，不用文字子串代替剧情质量评审。独立读者仍须检查中英含义一致、失联到求援的因果、失败不冒充成功、雨林衔接以及未提前揭晓月球。本次检查不证明剧情跳过运行正确，也不证明沙漠已可玩、音画合格或六关已完成。
