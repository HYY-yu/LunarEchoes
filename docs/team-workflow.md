# 游戏团队运行协议

本协议将六关战役拆成可验证的 Issue 与 PR。角色配置是可复用指令，不是四个常驻进程，也不包含后台唤醒器。

## 启动主协调

在本项目的 Codex chat 中使用以下提示词。快速盘点可用 Medium，跨模块追查原因可用 High，多项原因可能相互影响时考虑 Extra High。按这次任务的调查深度选择。

```text
按 AGENTS.md 和团队协议协调《月面回响》。核对六关现状、开放 Issue 和 PR，推进一项依赖已满足的任务。
任务可独立推进时按需使用子 Agent。为每项任务指定 owner、可观察的完成条件和证据。
完成条件是当前 PR head 的独立领域验收与 CI 均通过。按合并授权和人类决策条件关闭本轮。
报告结果、证据、实际阻塞和需要人类决定的事项。
```

主协调按依赖、运行环境容量和任务规模安排并行，保留独立验收所需容量。共享模拟或其他模块只有一个写入者。同机运行时协调构建、测试和浏览器等重型任务，避免重复占用 CPU 和内存。验收完成后停止自己启动的进程并清理本次不再需要的临时文件，保留验收日志和媒体证据。

角色文件位于 `.codex/agents/`，遵循 [Codex custom agents 格式](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)。客户端是否已加载角色需实际确认；不能仅凭文件存在声称团队已启动。模型和权限继承父会话，不在角色文件里扩大权限。

## 按 Issue 推进

1. 主协调读取当前 main、开放 PR、Issue 和验收记录，选择依赖满足的任务。
2. 每个 Issue 指定一个 owner，记录范围、依赖、预期行为、验收命令、实际使用场景、所需证据与人类决定。
3. 每名写入者为自己的任务创建独立 worktree、分支和 PR。只有 owner 推送、rebase 或改写自己的分支。
4. owner 提交小范围 PR，并附最新 head SHA、实际验收输出与剩余限制。
5. 非作者 verifier 对当前 SHA 执行领域验收。视觉检查实际截图或动画，音频检查听感与生命周期，数值检查可复跑数据。
6. integration_manager 读取远程最新 SHA、CI 与验收，核对范围和风险。它不代替领域 verifier 阅读深层实现。
7. 满足下表才合并。合并后运行下一任务依赖的 main 验收；出现回归则建立缺陷 Issue，暂停依赖任务。

| 类型 | 必要证据 | 处理 |
|---|---|---|
| 已授权范围内的低风险改动 | 当前 SHA 的可执行验收、独立 verifier 通过、`verify` 成功、已有 required checks 全部成功 | 在既有合并授权内推进 |
| 重大调整 | 方案与影响、人类决策 Issue、当前 PR 与 SHA | 保留 PR，等待人类明确决定 |
| 检查缺失、失败或状态未知 | 失败输出、缺失项或权限错误 | 不合并，派回 owner |

合并前核对 GitHub 上当前生效的保护和 required checks。已有团队验收条件仍全部适用。按既有授权逐个推进合并，保持 auto-merge 关闭，沿用当前保护规则和凭据。

人类决策至少包括重大剧情重写、重大美术方向变化、核心玩法或节奏变化、关卡顺序、每关时长范围、战役解锁规则、存档与回放协议、大型依赖、性能预算放宽、收费和新增追踪。作者不能自行将这些改动降为低风险。CI 成功与用户沉默均不构成批准。批准后若方案或 SHA 改变，重新核对决定适用范围并验收。

## 四类职责

| 角色 | 拥有的结果 | 交付证据 |
|---|---|---|
| story_director | 连续六章、地图叙事、目标、对白和中英文 | 剧情连续性清单、内容检查、可跳过剧情的运行证据 |
| visual_audio | 游戏 UI、代码像素人物怪物动画、动效和合成声音 | 实机截图、动画片段、音频样本与听感记录 |
| balance_performance | 每关 180–300 秒、数值、包体和渲染性能 | 多策略种子结果、实际 gzip、明确设备的帧时间记录 |
| integration_manager | PR 增量、检查和 Issue 队列 | 最新 SHA 的检查结果、独立验收、决定记录 |

## 验收与巡检

交付按 [verify-lunar](../.agents/skills/verify-lunar/SKILL.md) 执行。先确定能证明目标行为的验收，缺少覆盖时先补验收再推进实现。Issue 写明受影响的关卡、语言与交互及各自预期结果。保留关键测试与断言，失败必须如实报告。

PR、main push 和手动触发均运行 [GitHub 验证工作流](../.github/workflows/verify.yml)。合并时以当前 head SHA 对应的实际运行结果为准。

巡检须由已授权的外部触发器启动。在执行环境中核对触发器状态、实际唤醒与权限。角色配置只定义职责。

每轮巡检读取最新 main，运行 `npm run verify`，并最多推进一件可验收的小任务。integration_manager 按关卡、错误类别和稳定复现键查找已有 Issue，更新已有问题或创建新问题，附日志、SHA、复现与验收，并向主协调提出领域分派。通知只报告完成、失败、真实阻塞或需要人类决定的事项。
