# 六关战役路线

本文件是待实施的剧情与内容计划。当前游戏只有月面原型，没有六关战役、跨关解锁或持久存档。用户确定每关战斗 180–300 秒，六关战斗总计 18–30 分钟，不含剧情和菜单；剧情可跳过，文本支持中文与英文。

主角是地球防卫部队的中继工程兵。外星机械生物通过月球信号网络侵入地球，主角从求援、防守逐步转为反攻，最终切断月面入侵源。自动攻击、走位、冲刺和升级构筑保持既有玩法，不增加新的核心玩法。

以下敌人名称和细节是供 story_director 打磨的初稿，重大主线调整须保留 PR 等待人类决定。

| 关卡 | 地图与空间差异 | 任务与故事推进 | Boss 与新增内容 | 入场和下一关线索 |
|---|---|---|---|---|
| 1 沙漠基地 | 沙丘、雷达阵列、破损机库；开阔地与设备间隙形成不同走位通道 | 守住求援信号，确认入侵并非孤立事故 | 钻地收割机；基础爬行敌、冲刺预警、脉冲步枪教学 | 接到失联警报；恢复的遥测指向雨林研究站 |
| 2 雨林深处 | 林冠阴影、遗迹空地、盘根通路；植被保证轮廓与预警可读 | 取回研究站数据，发现外星生物由同一信号同步 | 孢子母体；成群近战与缓慢远程敌，绿色发光组织 | 沿沙漠遥测追踪；解码结果指向南极接收阵列 |
| 3 寒冻南极 | 冰原、裂隙边缘、极地观测站；白地上使用清晰深色轮廓 | 守住阵列，定位月球发射源并拿到反攻坐标 | 冰壳巨兽；装甲精英与扇形弹幕 | 研究数据提供频率；轨道窗口即将关闭，必须赶往电梯 |
| 4 太空电梯 | 狭长运载平台、轨道井、维修甲板；纵向空间与重复舱段表现上升 | 在运载期间抵抗追击，将反攻设备送入轨道 | 轨道猎手；飞行追击敌和定向射击预警 | 带着坐标上行；出口空间站哨塔遭围攻 |
| 5 保卫哨塔 | 哨塔周围环形防线、掩体缺口、对接平台；多方向敌潮 | 在月球出发前守住最后的轨道中继，完成反攻充能 | 攻城指挥体；前四关敌类组合与阶段敌潮 | 电梯抵达受损空间站；充能成功打通月球航线 |
| 6 月面回响 | 灰白月壤、陨石坑、异星月球基地与核心区；复用并扩展现有月面资源 | 清除外星月球基地并关闭入侵网络，让地球重新接通信号 | 月面主脑；已有收割者资源可作为精英或 Boss 初稿 | 哨塔提供坐标和窗口；胜利后回收前五关信号片段，完成故事闭环 |

地图首先通过布局、地形视觉、基地建筑和敌潮配置形成差异。视觉装饰不能暗示不存在的碰撞或掩体功能。地图障碍、目标防守判定或移动规则若需新增模拟机制，先明确行为与验收，再由主协调划分独立任务。

## 分批任务与依赖

以下任务按依赖转成 Issue；实时状态以 GitHub 为准。共享契约首项见 [Issue #1](https://github.com/HYY-yu/LunarEchoes/issues/1)，输入边界与验证样例见[六关数据契约](stage-contract.md)。契约 PR 合并才代表 A1 的数据契约部分完成，不代表模拟已接入或六关已经可玩。每项建立独立 owner、worktree、分支与 PR。

| 批次与任务 | 依赖 | 主责角色 | 完成验收 |
|---|---|---|---|
| A1 共享关卡契约 | 团队基础 PR | 主协调派发技术 owner，story_director 与 balance_performance 提供约束 | 关卡 ID、时长、地图、敌潮、Boss、双语内容结构；两种关卡数据可加载；版本与回放行为明确 |
| A2 战役解锁与失败重试方案 | A1 | story_director 提案，技术 owner 实现 | 人类确认解锁与重试规则；未解锁不可进入、成功只解锁一次、刷新行为有约定和测试 |
| A3 角色和怪物动画、音效清单 | A1 | visual_audio | 实际图集动画、预警、静音生命周期、缺失事件 Issue；桌面和窄屏证据 |
| B1 沙漠基地完整纵向切片 | A1、A3 | 技术 owner；三领域分别验收 | 从开场到 Boss、结算与下一关入口连续可玩；剧情可跳过；中英文；输入回放一致 |
| B2 沙漠体验与性能基线 | B1 | balance_performance | 多策略多种子结果，战斗 180–300 秒；实际包体、目标浏览器帧时间与人工试玩记录 |
| C1 雨林深处 | B2、A2 | story_director 内容 owner，visual_audio 与技术 owner 分任务 | 与沙漠显著不同的地图、剧情、敌潮；完整一局、双语、回放和视觉验收 |
| C2 寒冻南极 | C1 | 同上 | 明确南极线索接续、电梯出口；白地轮廓可读；完整一局验收 |
| C3 太空电梯 | C2 | 同上 | 平台上升的视觉表达；地图边界与预警清晰；完整一局验收 |
| C4 保卫哨塔 | C3 | 同上 | 已确认的防卫目标规则、敌潮节奏与月球出口；完整一局验收 |
| C5 月面回响 | C4 | 同上 | 复用月面原型并完成最终章；月球基地清除、故事闭环与最终结算 |
| D1 全战役回归 | 六关分别通过 | integration_manager 派发独立 verifier | 六关顺序与解锁、重试、双语、跳过剧情、回放版本、全量 verify、视觉与音频验收 |

沙漠首关的双语目录、跳过行为约定和未来视听验收见[沙漠基地剧情规格](desert-base-script.md)，该内容规格不代表 B1 已完成。

先用沙漠基地验证工作流、关卡接口和资源规格，再扩展内容。多个领域可准备不依赖实现的资料，但不得同时改写共享模拟或争用同一分支。每关数值调整都保留种子与操作策略，避免仅靠换皮宣称新关完成。

## 已确认的体验规则与待定技术

HYY-yu 已在 [Issue #8 的决定评论](https://github.com/HYY-yu/LunarEchoes/issues/8#issuecomment-6679991092) 确认三项体验规则。失败只重试当前关，已解锁不回退。每次进入关卡重新构筑，不继承上一局装备、等级、经验或当前装甲。当前浏览器本机只保存已解锁关卡，不保存进行中的战斗。完整记录与后续验收草案见[战役进度与失败重试决定](campaign-progression-proposal.md)。记录决定不代表 A2 已实现或六关已经可玩。

具体主角身份、对白和敌人命名仍由 story_director 提案。存档字段、格式版本、写入时机、失败恢复、重试种子规则及跨关录制方式仍未定案。任何回放协议或 checksum 语义变化、护塔新耐久或失败条件都须另行提案并取得人类决定。第一轮保持既有单局构筑行为。
