# 本机解锁存档与按关回放技术决定

本决定服务于 [Issue #14](https://github.com/HYY-yu/LunarEchoes/issues/14)，稳定复现键为 `campaign.protocol.save-replay-v2`。目标是让玩家在当前浏览器保留解锁进度，并让一局回放明确绑定原关卡与规则。HYY-yu 已于 2026-11-06 在[决定评论](https://github.com/HYY-yu/LunarEchoes/issues/14#issuecomment-6684779269)批准两组方案。决定基于文档 head `77e01438e8828e7712277c5358fc60604a0f60ae`，并细化异常恢复为发现坏数据或未知版本时立即请求确认重置，取消则临时游玩且明确不保存。第二组采用不兼容旧数据的新回放协议，重试生成新种子。

本文记录上述决定及本次细化，没有实现存档、战役入口或新回放。文档合并不代表功能已实现，也不批准护塔新耐久、失败条件或本文之外的新语义。

## 已确认的边界与现状

[战役进度与失败重试决定](campaign-progression-proposal.md) 已确认死亡只重试当前关，已解锁不回退，每次入关重置构筑。浏览器只存解锁进度，不存局中战斗。六关顺序沿用 `STAGE_ORDER`，依次为 `desert-base`、`rainforest`、`antarctica`、`space-elevator`、`watchtower`、`lunar-echoes`。每关战斗仍为 180–300 秒，剧情单独计时且可跳过。

本决定以 `9577d9a2ccfe90aa4603e1c98dbecaf5ddfb3302` 为源码基线。`src/core.ts` 的 `VERSION` 为 `lunar-1`，`Recording` 只有 `version`、`seed`、`actions`。`replay()` 只检查版本，然后从种子创建单局并依次分派动作。`checksum()` 对去掉临时 `events` 的 `World` JSON 做 32 位 FNV-1a 风格校验，不含显式关卡或规则标识。

`src/main.ts` 的 `recording`、`lastRecording` 与 `lastChecksum` 都在内存中。终局复制动作并保存 checksum，页面刷新即丢失。浏览器回放入口直接从种子创建原型世界，结束后比较独立保存的 checksum。当前没有 `localStorage`，没有六关加载或持久解锁。`src/stage-contract.ts` 已有六关 ID，但两个契约样例并非可玩关卡，`main.ts` 尚未接入它们。

本决定不增加账号、云同步、外部传输、回放导入导出或新种子玩法，不改变固定 60 Hz 模拟。浏览器存储、菜单、日志与播放控制留在模拟外，渲染与音频不得修改战斗状态。

## 决策一采用最小解锁存档并保留不可读数据

采用一个本机 `localStorage` 项，key 为 `lunar-relay.campaign-progress`，内容为 JSON。字段只表达解锁边界。

```json
{
	"version": 1,
	"highestUnlockedStageId": "desert-base"
}
```

`version` 是存档格式版本，与回放版本独立。`highestUnlockedStageId` 必须是 `STAGE_ORDER` 中的一个 ID，其前缀全部视为已解锁。不存重复的列表、装备、等级、经验、装甲、种子、动作、进行中关卡或通关次数。第六关胜利显示结局，存档仍最多指向 `lunar-echoes`。本方案不持久记录“已经看过结局”。

读取边界要求普通对象、两个已知字段、精确的版本整数和已知关卡 ID。JSON 损坏、缺字段、多余字段、未知版本、未知关卡或错误类型均拒绝，不做猜测式迁移或截断。未来版本需要另提迁移方案。

已批准的写入与恢复行为如下。

- key 不存在时，从第 1 关开始，不因打开页面创建存档。
- 只有真实游玩从未终局转为 `won`，才计算下一关。只授予紧邻下一关，重复处理或重玩旧关均取当前与候选的较高解锁边界。第 6 关不生成新 ID。失败、回放、剧情跳过、语言切换与菜单操作不产生胜利授权。
- 新解锁先保留在本次会话，再尝试保存。写入成功且核对读取一致才显示“已保存”。写入前失败时保留原存档字符串；写入操作抛错时不主动删除旧值。若写入返回成功但核对读取抛错或不一致，持久状态视为未知，不能承诺旧值仍在。写入前读取失败或写操作失败显示“未保存”，写入后核对失败或不一致显示“保存未确认”。两类失败均保留会话解锁，不撤回胜利，也不盲目回滚覆盖可能已写入的新值。后续真实新解锁可重试保存完整的会话进度，不增加定时写入或逐帧写入。
- 每次准备写入先重新读取该 key。有效旧存档与会话进度取较高边界，避免常规重载导致回退。若发现坏数据或未知版本，停止自动写入并立即说明原因、请求确认重置。读取异常时进入会话未保存状态，不覆盖无法读取的原值。
- 启动时发现坏数据或未知版本，先保持原 key 的原字符串不变，立即说明具体原因并请求确认重置，不等玩家自行寻找重置入口。不开放无法验证的进度。取消不写入、不清除原值，明确告知本次仅临时游玩、不能保存，并从第 1 关开始。若是在已有会话中发现异常，取消保留当前会话解锁。读取被浏览器禁止时进入会话模式，不尝试覆盖未知原值。
- 进入上述保护状态后，本次会话的胜利也不得自动覆盖该 key。玩家可继续游玩，并按实际失败阶段看到“未保存”或“保存未确认”。刷新后只恢复当时可读取并通过验证的进度。写入后核对失败时，新增进度可能已经写入，但无法确认，不保证刷新可恢复。
- 提供显式“重置本机进度”，先说明会删除旧进度并要求确认。确认后写入第 1 关的新格式并核对成功，才重置会话解锁并退出保护状态。重置在写入前失败时保留原字符串。若写入成功后核对失败，旧值可能已被替换，报告存储状态未知，不承诺旧字节仍在，也不盲目回滚。写操作失败时明确说明重置未完成，保留当前会话进度和保护状态。写入后核对失败或不一致时单独反馈旧数据可能已替换、当前会话保留、保护继续，不盲目回滚。取消不修改任何值，并告知本次临时游玩不能保存。只有写入并核对成功才显示重置成功。

本机保存只承诺当前站点、浏览器与设备的进度，不保证浏览器清理或隐私模式结束后仍存在。多标签页没有原子比较写入能力，本方案不承诺并发游玩同步。后续实现必须验证顺序打开标签页不会覆盖较高的有效解锁；若要保证并发一致性，另提存储方案，不在本任务增加锁或数据库。

未采用的替代方案是在坏数据或未知版本时自动重置并覆写第 1 关。这会永久丢弃可能可恢复的旧进度，也可能破坏新版存档，因此未采用。保留原字符串的代价是玩家需显式重置后才能恢复保存，提示必须说明这一点。两种方案都不能把损坏数据当成未知关卡的授权。

## 决策二采用关卡与规则版本绑定的单局录制

采用“一次入关，一份录制”。重试与进入下一关都创建新世界和新录制，不连接成整轮战役动作流，不携带上一局构筑。当前原型的新局入口生成 uint32 种子并录入。已批准重试继续走新局入口生成新种子。新种子让每次重试有变化，但也允许玩家通过重试寻找有利种子，配对验收需保留原种子。未采用的替代方案是在当前关重试时固定失败局的种子，便于重复挑战同一局势，但重复内容更多，也不能消除玩家重开新局寻找种子的动机。本决定不增加种子选择界面。

后续实现将 `VERSION` 升为 `lunar-2`，作为新 Recording 格式与模拟兼容边界。任何会改变动作解释、初始状态、模拟结果或 checksum 语义的修改都必须更新对应兼容版本，不能只改文件后继续接受旧录制。每关另有受控的 `rulesVersion`，绑定该关精确的模拟配置，包括战斗时长、地图中影响模拟的边界、敌潮、Boss、初始构筑与胜负规则。规则版本在批准的关卡目录内解析，不从录制加载任意配置。双语文案、纯视觉与音频不改变该版本。

以下是未来终局录制的字段示例，表示已批准的目标结构，不是当前类型。示例规则版本须在对应关卡实现时绑定精确配置。

```json
{
	"version": "lunar-2",
	"stageId": "desert-base",
	"rulesVersion": "desert-base-1",
	"seed": 208907,
	"actions": [],
	"finalChecksum": "01234567"
}
```

`actions` 沿用 `tick`、`choose`、`pause`、`resume` 的有序语义。示例空数组仅展示字段，不能作为已完成战斗的验收样本。`finalChecksum` 在真实终局生成，录制与预期校验一起保留在内存，不加入解锁存档。刷新仍丢失录制，不隐含回放存储功能。

加载前先校验完整结构、uint32 种子、动作类型与数值，以及精确匹配的 `version`、`stageId`、`rulesVersion`。纯回放入口与浏览器播放入口必须走同一检查，不能沿用当前浏览器直接 `createWorld(seed)` 的绕过路径。旧 `lunar-1` 录制缺少关卡上下文，一律明确拒绝，不推断为月面或自动升级。

关卡 ID 已知也不代表关卡已实现。目录缺失、规则版本不匹配或关卡尚未接入可玩模拟时，在创建或替换当前世界前拒绝加载。真实选关同样要求“已解锁且已实现”，缺关显示暂不可用，不能静默落回月面原型。回放按录制上下文重建初始状态，不读取玩家解锁存档来补充世界状态。

终局校验绑定上下文。沿用现有 `checksum(world)` 的状态取值和哈希算法，再对固定顺序的 JSON 数组 `[version, stageId, rulesVersion, seed, checksum(world)]` 使用相同哈希算法，结果作为 `finalChecksum`。此录制校验语义已随 `lunar-2` 获批，后续实现须与本约定一致。实际实现不得依赖任意对象键顺序拼接上下文。校验用于发现回放偏离，不是防篡改证明，也不赋予本机存档可信安全性。

播放结束必须比较终局绑定校验。校验不符显示失败，记录预期值与实际值，不宣称回放验证通过。无论回放胜利、失败、中止、拒绝或校验不符，都不能派发真实战役胜利或写进度。回放模式与真实模式由会话入口固定，不能从世界的 `won` 单独推导授权。

未采用的替代方案是在每份录制携带整份关卡配置快照。快照可减少对旧目录的依赖，但仍需兼容旧模拟代码，不能保证跨代码版本可重放。它还增加录制体积、快照解析与数据校验的复杂性，因此未采用。已批准方案不保留历史规则运行器，规则更新后的旧录制明确拒绝，不承诺永久兼容。

未来实现沿用当前本机日志，不新增远程追踪。Info 记录真实解锁、保存成功、显式重置成功与回放开始结束，Debug 记录关卡和规则选择。Warn 记录被拒绝的存档、兼容性拒绝与会话降级，Error 记录存储操作异常、重置失败与回放校验失败。错误包含稳定原因码和阶段，回放日志附版本、关卡、规则、种子和动作数。不得吞掉异常或输出原始坏存档、完整动作流。存储异常同时展示对应语言的反馈。

## 后续实施的验收约定

后续实现需把下表转为可执行行为测试，并由非作者在当前实现 head SHA 独立复跑。存储测试使用可注入的读写边界，浏览器复核实际反馈与刷新行为。回放测试使用真实录制动作，不能只用空数组或构造一个 `won` 状态充当通关证据。

| 输入或操作 | 必须断言的结果 |
|---|---|
| 无 key 首次进入 | 只解锁第 1 关，不写存储；未解锁直接入口被拒绝 |
| 合法 version 1 存档后刷新 | 恢复对应前缀；回到选关，无局中战斗或构筑 |
| 第 1 关真实胜利并重复处理同一结果 | 第 2 关只解锁一次，不开放第 3 关；重复结果不重复写入 |
| 重玩旧关获胜、死亡重试 | 解锁不倒退；重试从当前关初始构筑和新录制开始，每次调用新局种子生成路径并录入该次种子，不固定复用失败局种子 |
| 第 6 关真实胜利 | 显示结局，最多六关，无第 7 关；刷新仍仅恢复解锁 |
| 战斗中刷新、跳过剧情、切换语言、播放回放 | 不新增解锁；刷新不恢复战斗，回放不改存档原字符串 |
| 畸形 JSON、错误字段类型、未知关卡、未知版本、多余字段 | 立即分别提示无效数据或未知版本并请求确认重置；确认前原字符串逐字不变，不自动覆盖或开放未知关卡 |
| 读取、写入、保存后核对读取分别抛错 | 异常被记录且反馈；保留会话解锁，不显示保存成功。写入前失败保留原文，写入后核对失败或不一致报告“保存未确认”，不声称未保存或存储不可用，不盲目回滚 |
| 异常提示后取消重置 | 无写入、无清除；明确临时游玩不能保存，启动时从第 1 关开始，已有会话保留解锁；后续会话胜利不覆写 |
| 异常提示后确认重置并写入、核对成功 | 此前不改会话解锁，成功后才重置为第 1 关并退出保护状态，显示重置成功 |
| 重置写操作失败 | 当前会话保留、保护继续，显示重置未完成，不声称成功 |
| 重置写入成功但核对失败或不一致 | 单列双语反馈旧数据可能已替换，当前会话保留、保护继续；不声称旧字节仍在、不自动回滚 |
| 页面开始后存档被换成较高有效进度或未知版本 | 下一次保存先读取；较高进度不回退，未知版本原文不被覆写 |
| 已解锁但目录缺关或尚未实现 | 真实入关与回放均明确拒绝，不创建月面替代世界 |
| 相同新录制与精确规则重放两次 | 初始构筑相同，动作顺序相同，终局与绑定校验一致 |
| 旧 lunar-1、未知格式、错误关卡、错误规则、无效动作 | 纯接口和浏览器入口均在替换世界前拒绝，显示相应双语原因，进度不变 |
| 保持世界校验输入不变但替换绑定上下文 | 绑定校验变化；不能用另一关的终局校验宣称验证成功 |
| 故意修改一条能影响结果的动作 | 回放校验失败，不授予解锁，不展示验证通过 |

实现任务须运行 `npm run verify`，再按项目验证技能真实试玩。关卡尚未实现时，测试夹具只能证明协议行为，不能证明六关可玩或 180–300 秒体验达标。本轮仅文档审阅，不进行浏览器、音频、美术、数值或性能验收，也不以文档 CI 冒充这些证明。

两组决定的来源为 [Issue #14 的人类评论](https://github.com/HYY-yu/LunarEchoes/issues/14#issuecomment-6684779269)。自动清档、配置快照与固定失败局种子均未采用。后续另建实现任务，记录实现 head SHA、独立验收与 CI。更改本决定中的解锁、异常恢复、兼容或校验语义须重新取得人类决定，不能把本次文档定案扩大为新增玩法或已完成实现。
