# Issue 36 方案 A

本方案把临时月面战场替换为横向沙丘、破损机库和雷达阵列构成的沙漠基地。只设计渲染边界，不实现，不改变战斗行为。

## 现有渲染如何工作

`src/render.ts` 的 `createRenderer(canvas)` 初始化角色图集和一块 256×256 月壤纹理，返回每帧的 `render(world, time, title)`。每帧从 `stageRules(world.context).arenaSize` 读取场地边长。当前规则给出 1500。

渲染器先将画布设为 CSS 尺寸的一半，再按宽度决定 0.8 至 1.2 的缩放。战斗相机跟随玩家，标题相机停在约 `(700, 660)`。变换后的坐标直接使用模拟世界坐标。

背景目前内嵌在 `render.ts` 中。绘制顺序为重复月壤、100 单位网格、内缩虚线、四组建筑、中心发光中继台，然后才是拾取物、敌人、弹道、玩家和特效。世界绘制结束后恢复变换，添加屏幕暗角和标题模式的地球图案。

`src/desert-scene.ts` 是独立的 320×180 剧情插画，绘制开场、胜利和失败。它没有战场相机，也没有世界布局。不能把这张侧视插画放大充当战场。

`src/stage-rules.ts` 拥有关卡范围与时长。背景模块只接收从这里解析出的场地边长，不接收 `World`。`docs/desert-base-script.md` 要求沙丘、机库和阵列建立空间关系，同时明确装饰不承诺碰撞、掩体或阵列耐久。

## 模块边界与调用端

新增单一文件 `src/desert-map.ts`。该文件拥有沙漠调色板、确定性布局、像素绘制和一张静态缓存画布。它不注册关卡，不创建通用场景树，不引入 registry。`desert-scene.ts` 保持剧情插画职责。

建议的类型与签名如下。以下只是接口草图，不是实现。

```ts
type DesertMap = Readonly<{
	draw(ctx: CanvasRenderingContext2D, arenaSize: number): void;
}>;

export function createDesertMap(): DesertMap;

function buildDesertMap(arenaSize: number): HTMLCanvasElement;
function paintSand(ctx: CanvasRenderingContext2D, arenaSize: number): void;
function paintDuneBands(ctx: CanvasRenderingContext2D, arenaSize: number): void;
function paintBaseRemains(ctx: CanvasRenderingContext2D, arenaSize: number): void;
```

调用端只新增一次创建和一次绘制。

```ts
const desertMap = createDesertMap();

const arena = stageRules(world.context).arenaSize;
ctx.save();
ctx.scale(zoom, zoom);
ctx.translate(vw / 2 - cameraX, vh / 2 - cameraY);
desertMap.draw(ctx, arena);

ctx.restore();
```

拾取物、敌人、弹道、玩家和现有效果仍放在 `draw` 与 `restore` 之间。`render.ts` 继续拥有相机和缩放。`desertMap.draw` 不读取或推算角色位置，也不接收真实时间。

每个 renderer 只拥有一张地图缓存。第一次绘制或 `arenaSize` 改变时重建，尺寸为 `arenaSize × arenaSize`，不乘设备像素比。1500 场地的像素存储约 9 MB，这只是设计估算，浏览器实际内存另验。窗口改变、标题切换和重开不生成新的同尺寸缓存。没有序列化位图，没有下载资源，没有运行时依赖。

## 布局与尺度

所有坐标按 `A = arenaSize` 计算并取整。下表同时列出 A 为 1500 时的近似值。空间关系是西机库、中央开阔地、东雷达，沙丘带从西向东贯穿。

| 元素 | 坐标与范围 | 1500 场地尺度 | 视觉处理 |
|---|---|---|---|
| 中央开阔地 | `x = 0.36A..0.64A`，`y = 0.34A..0.70A` | 420×540，中心约 `(750,780)` | 仅细沙与稀疏轮胎印，无高反差杂物 |
| 西机库残迹 | 左上 `(0.17A,0.35A)`，宽 `0.16A`，高 `0.12A` | 左上 `(255,525)`，240×180 | 无顶棚、无完整立墙，地面地坪和外翻倒塌梁识别机库 |
| 西机库前坪 | 左上 `(0.23A,0.47A)`，宽 `0.17A`，高 `0.09A` | `(345,705)`，255×135 | 沙覆盖地坪，轮胎印通向中央，东侧开口宽至少 110 |
| 东雷达阵列 | 左上 `(0.72A,0.34A)`，宽 `0.13A`，高 `0.15A` | `(1080,510)`，195×225 | 倒伏碟面、扁平支架、齐地基础，北上南下可从纹理识别 |
| 雷达设备间隙 | `x = 0.73A..0.86A`，`y = 0.51A..0.64A` | 195×195 | 断开的地面设备基座，间距至少 90，无闭合围栏 |
| 南侧辅助残骸 | 左上 `(0.60A,0.79A)`，宽 `0.09A`，高 `0.05A` | `(900,1185)`，135×75 | 低对比散落板材，不能像完整集装箱 |
| 北沙丘带 | 中心 `y = 0.18A`，起伏不超过 `0.045A` | 中心 y270，起伏约 68 | 宽缓曲线和短阶梯亮边 |
| 中沙丘带 | 中心 `y = 0.48A`，起伏不超过 `0.025A` | 中心 y720，起伏约 38 | 机库和阵列附近压低对比，中央主动断开 |
| 南沙丘带 | 中心 `y = 0.77A`，起伏不超过 `0.04A` | 中心 y1155，起伏约 60 | 较宽沙纹，保留大片平滑负空间 |

沙丘不是山墙。只画沙面受光侧、过渡色和稀疏顺风沙纹，不画黑色断崖边。轮胎印只用于连接机库前坪与阵列，不能组成规则方格。地表主色使用暖沙黄和赭色，金属使用现有深钢蓝及浅灰。青色只留少量设备标记，避免与角色、拾取物和脉冲效果竞争。

机库约为工程兵 16×16 帧以 1.7 倍绘制后的宽度的九倍。它有足够尺寸表达破损轮廓，但不占据中央交战区域。窄屏无法同时容纳两个地标，验收应分别移动至西、中央、东拍摄，不能通过缩小所有角色换取全景。

## 绘制层顺序

1. 先画地图外的更暗沙色，再画有效范围内的暖色基础沙地。外部保持同一沙漠材质，取消太空背景。
2. 在静态缓存上画低对比细沙颗粒。使用固定整数序列或坐标散列，避免重复月壤纹理和陨石坑。
3. 画三条横向沙丘带。沙丘起伏由固定控制点定义，不取真实时间。
4. 画被沙掩埋的机库地坪、设备基础和断续轮胎印。
5. 画倒塌机库梁、倒伏雷达碟面和少量地面板材。它们全部位于角色下方。
6. 在地图边缘画窄幅风积沙过渡。若表达世界范围，只将色差严格放在 0 与 A 的实际边界，不保留现有内缩 36 的虚线。
7. 由现有 `render.ts` 绘制拾取物、攻击预警、敌人、弹道、玩家和效果。
8. 恢复屏幕坐标后保留轻度暗角。标题模式继续使用沙漠背景与现有遮罩，删除地球圆盘。

缓存只包含第一至第六层中的有效地图内容。地图外的沙色填充由 `draw` 在世界坐标中补齐。绘制模块在自己的 `save` 与 `restore` 内处理样式，不能泄漏 `globalAlpha`、复合模式、线型或变换。

## 避免假碰撞

当前没有建筑碰撞。地图不能用完整直立围墙、完整屋顶、铁丝网或带硬投影的封闭设备箱暗示玩家会被阻挡。

机库是屋顶完全坍塌后的地面遗址。残梁画成断开的平面短段，沙子覆盖边缘。雷达使用倒伏并破裂的碟面与低基础，不画竖直塔架与长实体阴影。两类地标的深色线条保持细而断续，脚下路径仍能看清。

角色始终画在这些遗址之上，不进行基于 y 值的建筑遮挡。敌人、子弹和攻击预警经过时完整可见。设备间隙只是视觉疏密，不构成额外通道限制；文案不使用“躲到机库后”“掩体”或“修复阵列耐久”。

若实际截图仍把遗址读成不可穿越的建筑，应进一步删除墙面与阴影。不能通过修改 `World`、`core.ts`、输入或碰撞逻辑解决本 Issue 的表达问题。

## 删除范围

从 `render.ts` 删除旧 `terrain` 初始化、月壤 `noise`、陨石坑绘制和 `structure` 函数。删除四组月面建筑、100 单位网格、内缩虚线和中心中继台。删除标题模式地球图案。所有这些调用在同一改动中迁移或删除，不保留未调用的月面 helper。

不删除角色图集，不改玩家动画计时，不改敌人预警、子弹、效果、相机接口、`stageRules` 或剧情插画。没有未来六关分发逻辑。

## 可执行验收建议

设计文档没有执行以下验收。实现后由 owner 提供运行结果。

- 运行 `npm run verify`。同种子与动作序列的终局、tick 和 checksum 保持一致，且现有包体预算不变。
- 在固定浏览器和固定画布尺寸下，对同一场地连续绘制两次背景，比较像素完全相同。新建两个 renderer 的背景也必须相同。
- 将 `Math.random` 设为抛错后创建并绘制背景，确认背景不依赖未种子随机数。固定背景不读取 `Date.now` 或 `performance.now`。
- 冻结传入的世界对象与嵌套战斗集合后运行正常渲染，确认没有战斗状态写入。背景接口本身没有 `World` 参数。
- 绘制前设定非默认 transform、`globalAlpha`、`globalCompositeOperation`、线宽、虚线和 `imageSmoothingEnabled`。绘制后逐项比较，确认背景函数恢复调用前状态。
- 修改主画布尺寸，确认 Canvas 状态重置后背景依然正确。固定尺寸下背景缓存不逐帧重建。重开相同规则不叠加缓存。
- 使用 1500 与另一测试边长绘制背景，确认地标按比例布置，旧缓存不会被复用。测试值不写回正式关卡规则。
- 桌面 1280×720 与窄屏 390×693 分别检查西机库、中央空地、东雷达及四角。必须看见沙丘方向和基地空间，不能残留月坑、网格、中继台或地球。
- 在高敌群密度、敌人预警和 Boss 弹幕时录制片段。确认暖色沙地上原有橙色预警仍可读，必要时只降低地表亮边对比。
- 控制角色和敌人穿过每个地标，录制预警与弹道完整可见的片段。若遗址仍暗示阻挡，判定视觉验收失败。
- 记录当前 head SHA、浏览器控制台错误、桌面截图、窄屏截图和穿越地标片段。静态概念图不能替代这些证据。
