# 战役进度与失败重试决定

HYY-yu 已于 2026-11-06 在 [Issue #8 的决定评论](https://github.com/HYY-yu/LunarEchoes/issues/8#issuecomment-6679991092) 批准三项规则。失败只重试当前关，已解锁不回退。每次进入关卡重新构筑，不继承上一局装备、等级、经验或当前装甲。当前浏览器本机只保存已解锁关卡，不保存进行中的战斗。

本文记录三项体验决定，并同步 Issue #14 后续批准的技术边界。当前 `main` 仍是月面单局原型，本文档不实现战役、选关界面或存档，也不改变既有回放。

## 已确认的范围

六关依次为沙漠基地、雨林深处、寒冻南极、太空电梯、保卫哨塔、月面回响。每关战斗 180–300 秒，剧情可跳过，界面支持中文和英文。自动攻击、走位、冲刺与局内升级沿用现有玩法。关卡顺序与故事接续见[六关战役路线](campaign-plan.md)。

## 三项已确认决定与未采用的替代

| 选择 | 已确认 | 未采用的替代 | 体验与实现影响 |
|---|---|---|---|
| 失败后从哪里重试 | 只重试当前关，已解锁不回退 | 整轮战役从第 1 关重开 | 单关重试把一次失败的损失限制在当前关的战斗和构筑。整战役重开会增加前几关重复游玩，须定义整轮状态及死亡后的解锁处理 |
| 跨关是否保留构筑 | 每次进入关卡重新构筑，不继承上一局装备、等级、经验或当前装甲 | 把上一关结束时的装备和升级带入下一关 | 重新构筑让每关可单独平衡。继承构筑须定义装甲、经验和装备的携带范围，还会影响后续关卡难度及回放起始状态 |
| 解锁是否跨刷新保留 | 当前浏览器本机只保存已解锁关卡，不保存进行中的战斗 | 只在本次页面会话保留，刷新后从第 1 关开始 | 本机保存允许分多次完成六关，但清除浏览器数据或换设备会失去进度。只在会话内保留时，一次页面会话需完成六关，成功战斗总计 18–30 分钟，失败重试另计 |

已确认的组合保留每关的局内构筑，避免一次后期失败迫使玩家重打前五关。选关保留故事顺序，重试仍需重新完成当前关。这里没有永久属性、局外货币或额外核心玩法。

替代方案保留作原提案的比较记录，均未采用。若未来改为整战役死亡，需要重新确认死亡是否清除解锁，以及已解锁关卡还能否直接进入。否则玩家可能通过选关绕过重开规则。实现者不能自行更换已确认组合。

## 后续行为验收草案

以下展开三项决定的后续实现与验收场景，不是当前游戏能力。技术协议的已批准范围见下节与链接文档。

- 首次进入只开放沙漠基地，其他关卡显示未解锁。未解锁关卡不得通过任何入口进入。
- 关卡胜利后只解锁紧邻的下一关。重复处理同一胜利不重复授予进度，也不跳过尚未完成的中间关卡。
- 第 6 关胜利进入战役结局，不创建第 7 关入口。
- 失败后提供当前关重试与返回选关。重试不撤销此前解锁，也不携带失败局的装备、等级、经验或当前装甲。
- 每次进入已解锁关卡都开始新的一局。重玩旧关不降低最高解锁关卡，不重复解锁已经开放的关卡。
- 刷新或重新打开页面后回到选关，只恢复已解锁关卡。不恢复进行中的战斗，也不把刷新前未胜利的关卡算作完成。
- 跳过剧情与切换语言不改变解锁。关卡结果沿用该关已经确认的胜负规则，不新增护塔耐久或战役死亡条件。

本机保存不使用账号、云同步或外部数据传输。存储失败保留会话进度并反馈，写入后核对失败明确标记保存未确认。坏数据或未知版本不得开放未知关卡，先保留原文并立即请求确认重置；取消无写入、无清除，告知本次临时游玩不能保存。只有重置写入并核对成功，才重置会话进度并退出保护状态。

## 已批准的技术边界与仍需另批的变化

HYY-yu 已在 [Issue #14 的决定评论](https://github.com/HYY-yu/LunarEchoes/issues/14#issuecomment-6684779269)批准最小存档、真实胜利解锁后保存、异常恢复确认流程，以及按关新回放协议、不兼容旧数据和重试新种子。字段、版本、写入时机、两类重置失败、`Recording` 与上下文 checksum 约定见[本机解锁存档与按关回放技术决定](campaign-protocol-proposal.md)。技术决定不代表已经接入运行时，当前原型录制与回放仍保持不变。

后续实现必须隔离回放与真实进度，播放回放不授予解锁，也不覆盖真实游玩的进度。关卡已解锁但未实现时明确拒绝，不回退月面。护塔新耐久、失败条件及已批准范围之外的存档或回放语义仍需另行决定。未采用的跨关构筑继承若在未来重新提案，必须说明如何重建回放初始装备，不能只记录动作序列后声称可重复。

后续实现还需提供中文和英文的未解锁、重试、进度未保存、已通关与战役完成反馈。具体按钮布局、动画及音效交给视觉音频角色，最终用实际运行结果验收。本提案不预设界面已经完成。

## 后续验收场景

| 场景 | 应观察到的结果 |
|---|---|
| 首次进入或无可用进度 | 只可进入第 1 关。直接请求未解锁关卡也被拒绝 |
| 第 1 关胜利，重复派发结果 | 第 2 关只解锁一次，第 3 关仍锁定 |
| 当前关死亡并重试 | 回到同一关初始构筑，已解锁列表不减少 |
| 胜利后进入下一关 | 地图、剧情与目标按顺序接续，装备从新关初始状态开始 |
| 战斗中刷新 | 战斗不续接，该次未完成关卡不授予新解锁 |
| 胜利保存后刷新或重新打开 | 已解锁入口仍可用，不恢复上一局装备与战斗 |
| 重玩已完成关卡 | 可以重玩，不倒退进度，也不越级解锁 |
| 第 6 关胜利 | 显示战役结局，保持六关边界 |
| 跳过剧情、切换语言、播放回放 | 解锁不变，回放 checksum 与原局一致 |
| 存储失败或不可解析 | 向玩家反馈；不伪称保存成功，不开放未知关卡。按 Issue #14 已批准的异常确认、取消和两类写入失败约定验证 |

上述场景须在对应技术决定实现后，由非作者运行验收。当前文档的 `npm run verify` 与 CI 只能确认记录决定没有破坏现有项目，不能证明战役流程已实现。
