## 微信小游戏接入方案（设计，未实施）

- 产出 `docs/wechat-minigame.md`：现状体检、平台差异、四方案对比、目标架构、P0–P4 阶段、资质流程、风险与回退。
- 实测基线：`npm run verify` 通过，三 seed 全胜（208907/42/101），gzip 37,132 B / 153,600 B。
- 关键结论：包体不是瓶颈（主包 4 MB 上限，用量不足 6%）；成本全在 DOM UI（23 个容器、247 条 CSS 规则、`main.ts` 55 处 createElement）。
- 选定路线：视图模型 + 双渲染器（保留 DOM 渲染器，新增 Canvas 渲染器），平台端口层隔离 document/window/AudioContext/localStorage/crypto/matchMedia。`core.ts` 不改。
- 重要技术点：小游戏只有一个上屏画布，因此界面文字需画在全分辨率上屏画布，游戏画面由半分辨率离屏画布贴图，否则中文发糊。
